# OpenCode 云端托管 V0：第一条可交付主线

编写日期：2026-09-17。用途：交给 Codex 在目标仓库实施。

**本包是开发方案和验收约定，不包含已经实现的平台，不代表模型、部署或真实任务已经验证通过。**

## 唯一目标

工程师登录 → 进入自己预分配的云端工作环境 → 在一个授权项目中使用完整 OpenCode 修改代码、运行测试、检查 Diff → 下载可复用的变更 → 再次进入，原生会话与工作文件仍在。

这是一个小范围内部试用版本，不是公开多租户 SaaS。一个部署后端、一个平台配置、一类项目；默认每位试用用户一个独立环境。用户不配置模型、MCP、插件、Agent、网络或镜像。**不做本地电脑接入。**

## 怎么使用

1. 将本目录放入 Codex 能读取的目标工作目录。不要用本包覆盖仓库原有指令或未提交代码。
2. 让 Codex 读取 [CODEX_TASK.md](CODEX_TASK.md)，执行其中的任务。它会继续读取方案、验收和上游记录。
3. 模型凭据、登录配置、项目访问凭据通过受控环境文件提供，不粘贴到对话、不提交到 Git。先发现已有配置，确实缺失才集中报告。
4. Codex 必须实际修改、启动、测试和记录结果，不能以扩写文档代替实施。

可直接发送：

```text
读取 opencode-cloud-v0/CODEX_TASK.md，并按其引用的 PLAN.md、ACCEPTANCE.md、UPSTREAM.md 实施第一版。
只交付包中定义的一条云端编码闭环，不执行旧的三阶段开发包，不做本地连接器或通用 Agent 架构。
先证明固定版本的原生 OpenCode 在目标模型和容器里能完成真实代码任务，再接平台入口。
不要停留在方案描述；实际实现、启动并验证。缺少外部条件时报告精确阻塞，不编造结果，不转去扩大范围。
每次结束更新 STATUS.md：用户现在能做什么、不能做什么、验收证据在哪里、下一步只修什么。
```

## 文件

| 文件 | 用途 |
|---|---|
| [CODEX_TASK.md](CODEX_TASK.md) | 实施指令、工作顺序、停止规则 |
| [PLAN.md](PLAN.md) | V0 范围、架构取舍、接入与部署要求 |
| [ACCEPTANCE.md](ACCEPTANCE.md) | 10 组真实验收，定义交付终点 |
| [UPSTREAM.md](UPSTREAM.md) | 固定版本候选、已核实事实与仍需实测的边界 |
| [STATUS.md](STATUS.md) | 初始状态和后续交接记录；当前均未实施 |

## 取舍

保留“纵向切片、模块边界、真实结果验收”的原则；不采用多 Runtime 抽象、自有 Run/Tool 执行状态机或预设 Code/Work/Research 三阶段。平台是薄托管层，OpenCode 是唯一 Agent。

管理员按文档预先准备项目和启动环境，是 V0 允许的运营方式；每次工程师使用都要开发者修数据库、补目录、手工恢复会话，则不算交付。

## 本包自身校验

生成时只检查文件完整性、本地文档引用和 ZIP 可读性。这不是平台测试。所有软件验收以实施后真实产生的记录为准。
