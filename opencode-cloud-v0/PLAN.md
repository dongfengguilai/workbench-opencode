# V0 实施方案：把一个完整 OpenCode 交付给工程师

## 1. 产品契约

**交付目标：**工程师使用现有登录进入纯云端工作台，对一个授权项目完成真实代码修改与测试，检查 Diff、取得可复用变更；重新进入后，原生会话和工作文件仍可用。

**用户：**少量企业内部试用工程师，不是互联网匿名用户。至少用两个不同真实测试身份验证资源隔离。一种统一环境模板、一种项目技术栈、一个已批准模型路由。每个用户预分配一个独立环境和一份项目工作副本。

“完整 OpenCode”是保留原生循环、上下文、编码工具和交互，不等于开放系统管理权或所有高风险功能。平台强制配置、外部共享与远端写入限制是产品边界，不把原生 Agent 改成只返回文本的聊天服务。

### 用户步骤

1. 登录企业入口，看到一个明确的项目入口和环境状态。
2. 进入自己的原生 OpenCode 工作台；无需输入模型 Key、地址、MCP 或服务器 URL。
3. 提交真实修改需求；看得到模型响应、工具活动、必要的提问/确认。
4. OpenCode 在云端项目目录中读取、编辑、执行测试；用户可停止和继续交互。
5. 检查 Diff 与测试结果，下载相对固定基线的完整变更补丁。
6. 退出、刷新或重新登录后，找到同一原生会话和文件状态。

### 明确不做

本地连接器/设备管理/隧道/文件同步；用户环境配置；Harness/Cordis；多 Agent Runtime；独立 RunCoordinator/Dispatcher；自研模型循环、工具引擎和会话事件库；Kubernetes/自动伸缩/休眠唤醒；模板编辑器/技能市场/通用插件加载器；知识库/工单/多项目业务线；自动 push、PR、部署；通用 Artifact 服务。

首版允许管理员按文档预置项目和环境，不做动态创建系统。此简化不免除身份、隔离、数据保存和配置限制。

## 2. 架构：薄平台 + 完整实例

```text
浏览器
  │ HTTPS：现有身份体系
  ▼
平台单体（登录适配、固定授权映射、Web 静态资源/受控代理）
  ├── 用户 A → 内部环境 A → 完整 OpenCode → 项目 A + 原生状态 A
  └── 用户 B → 内部环境 B → 完整 OpenCode → 项目 B + 原生状态 B

运维：按固定清单启动 Compose，不由用户请求调用 Docker API
模型：批准的企业网关；必要时增加单提供方的受限转发
持久存储：每个环境独立工作目录 + 原生状态目录；平台不重建会话真相
```

OpenCode 的 Server/SDK 支持客户端与运行时分离；本方案复用这个边界。[S2][S3]

### 2.1 平台侧只做三件事

- 使用原有认证识别用户，检查身份是否启用以及与环境的绑定。
- 在固定映射中定位环境，检查健康后提供工作台访问。
- 在访问边界限制管理操作、跨环境请求、数据导出与长连接。

不通过新业务数据库控制模型一步步执行。固定授权和路由映射可以用服务端只读配置保存。已有认证需要的数据库照用，不为“平台完整性”新建 Session/Run/Tool 表、Redis 或队列。

### 2.2 固定运行形态

一个预分配环境 = 一个用户/项目信任边界。OpenCode、Bash、Git、语言服务和测试依赖在这个环境中看到同一份 `/workspace/project`。

环境预先启动，平台只查询健康和路由，不直接挂载 Docker Socket。维护者用 Compose 启停；首次登录不开发排队和调度。

项目只从受控基线准备一次；第二次启动不重新 clone 覆盖工作。准备目录非空时显式拒绝破坏性初始化。

同一环境可以保留多个历史会话，但 V0 同时只允许一个顶层写任务。必须识别忙碌状态并拒绝/明确排队，不能两个会话悄悄同时改同一目录。原生子代理保留为该任务内部能力，不开发跨实例任务分发。

## 3. 原生 UI 与访问路径：选择一个简单默认

默认部署一个 HTTPS origin：保留原生 UI 使用的根路径，平台页面/API 占用一个经检查不冲突的保留前缀（建议 `/__platform/`）。登录后，服务端按当前身份映射固定上游环境，不在浏览器暴露可任意填写的上游地址。

不假设原生 UI 天生支持任意 `/users/A/opencode/` 子路径，不做 iframe 拼装，不用正则改写所有 JS。若现有部署要求独立 origin，由运维配置固定 origin 并做完整认证验证；不要同时实现两套路由模式。

实现前检查固定版本的前端资源获取方式。必要时构建同 tag 的 `packages/app` 等实际入口，由平台静态托管；禁止未经确认在每次页面请求时获取滚动版本前端或把代码交互交给公开第三方 Web 服务。

### 最小 UI 裁剪

保留会话、消息、工具活动、文件/Diff、原生提问与操作确认、停止、续聊，以及固定版本已有且主线需要的终端能力。原生子代理不重做面板或框架；回归其必要交互。

隐藏并在服务端禁止：新增服务器、用户模型/Provider 配置、API Key/OAuth 配置、Agent 编辑、MCP/插件/Skills 安装配置、平台网络/镜像修改、公开共享与自动升级。允许主题/字号等纯显示偏好，以及用户用自然语言表达任务要求。

UI 修改记录成最小补丁，不另建聊天协议和工具执行状态机。

### 代理必须遵守的规则

- 每个请求、SSE 订阅和 WebSocket 升级都验证身份与绑定。身份来源是服务器验证的会话，不是 userId/envId Header。
- 退出、停用、过期时不只是禁止新连接，还应终止已授权长连接或在有界的短期再授权窗口内关闭；写操作必须检查当前权限。
- 浏览器传入的上游地址、Host、认证头、directory/workspace 参数不能改变绑定。规范化、校验或固定为受信任环境和项目。
- 实例端口不对浏览器或公网直接暴露。代理凭据按实例分配，由服务器注入，不返回浏览器。
- 按固定 OpenAPI/实际路由建立方法与路径允许清单。未列出的管理接口默认拒绝；同时验证消息体中 model/agent/system/tools 等覆盖入口，只接受平台允许的设置，不能仅封 `/config`。
- 允许清单是版本相关的托管补丁，不发明通用策略引擎。升级须重新核对。
- 向实例转发前去掉平台会话 Cookie、浏览器 Authorization 和非必要身份信息；只注入实例级认证。不得让可执行用户代码的环境得到平台登录凭据。上游 Set-Cookie、跳转目标和敏感响应头按清单处理。
- 保留原生流，不缓存/缓冲完整响应后才显示。断线补状态按原生接口重新查询，不虚构可重放事件序号。
- 假定会有重复点击和请求回执丢失：优先使用原生 message ID 机制查证；无法确认时显示不确定，不自动重发提示词。
- 同一浏览器切换账号时，清理或按用户隔离应用缓存、持久查询结果、localStorage/IndexedDB 和 Service Worker 缓存，避免展示上一个用户的历史；敏感 API 不进入公共缓存。
- 处理 cookie/CSRF/Origin 与安全头，不使用凭据型 `Access-Control-Allow-Origin: *`。
- 工作区 HTML、脚本和生成文件不能作为平台 origin 下的可执行页面发布；V0 以安全文本/下载方式处理，不添加任意服务预览代理。

## 4. 固定平台配置与安全上限

### 4.1 配置不只是隐藏按钮

OpenCode 当前文档中，配置按来源合并，Managed Settings 高于普通用户与项目设置；但高优先级不自动删除低层新增的所有键。[S4] **把 `/etc/opencode` 挂只读，只是措施之一，不是完整验收。**

必须核实固定版本的配置来源和插件自动发现路径：平台维护的设置、插件和 Agent 资源来自只读受信任目录；项目/用户可写目录不得借 `.opencode`、`opencode.json` 或动态 API 新增执行扩展、模型端点或平台权限。

优先使用该版本实际支持的控制项，保留 root 管理权限。若仍有漏洞，只做范围明确的受控加载/管理 API 补丁，并对真实读取路径测试，包含实例内部 loopback 的管理入口；不只在外层代理拦截。不要假设同 UID 下的 Shell 无法访问本机服务。

普通任务指令与项目说明仍可作为模型上下文；它们不能获得额外系统权限。若项目文件必须限制自动加载，不偷偷修改用户项目，应由受控启动/加载策略实现，并清楚展示限制。

### 4.2 执行隔离

OpenCode 官方说明其权限机制不是安全沙箱。[S5] 本版采用容器或已有专用虚拟机边界，不能依赖“模型不会执行危险操作”。

- 非 root、禁止特权模式、禁止宿主 PID/网络，限制 CPU/内存/PID/磁盘及任务并发。
- 只挂该环境项目与原生状态；不挂整个宿主目录、其他用户卷、SSH 主目录、Docker Socket。
- 管理配置与受信任程序只读；项目依赖可在受控的可写目录安装。项目 `package.json` 变更属于工作内容，不是平台配置权。
- 每个用户环境独立网络边界，不通过同一个扁平容器网络访问其他环境。
- 网络默认拒绝；允许固定模型入口与批准依赖源。2026-09-17 用户另明确批准公开 HTTPS 网站（443），通过每环境受控 CONNECT 网关校验全部 DNS 地址并固定公网 IP；直接外连仍禁止。阻断宿主机管理端口、云元数据、平台数据库和其他用户实例，普通 HTTP 与非 443 公网目标仍拒绝。
- 不能只设置 `HTTP_PROXY` 就宣称外连受控；须实测直接 IP、IPv6（若启用）和绕代理访问是否仍被拒绝。
- 不在工作容器提供仓库写凭据、生产服务凭据。首版不允许 push/创建 PR/部署；仅通过原生 permission 文案拒绝不构成这一限制。
- 不把 Docker 控制权限交给 Web 业务进程；容器运维操作只在维护者侧执行。[S6]

本版针对受控企业试用，容器加固不等于已完成对任意恶意多租户的安全证明。记录已验证边界，不夸大安全等级。

### 4.3 模型与凭据

优先使用已经批准的企业模型网关，指定一个模型和协议。不存在网关时，可增加一个固定提供方的受限转发入口：只转发本次模型所需路径，保持原生请求/流格式，不做多提供方抽象或自研模型 SDK。

长期上游密钥保留在网关/受信任转发端，工作环境只有有范围、可撤销的访问凭证。转发端固定目标，拒绝用户指定 URL 和超出范围的 model，限制并发/预算。不要把共享主 Key 放进所有用户容器。

原生 coding 基线必须使用最终交付所用的模型路径。代码、提示词和工具输出可能被发送至批准模型，需在使用说明中告知，不能宣传纯本地保密。

## 5. 认证、项目与数据

### 5.1 认证

保留既有登录机制；从旧工程读取真实实现后做最小适配，不从记忆编造 NetID 协议、Cookie 或字段。旧 README 表示真实内网 NetID E2E 依赖外部环境，本次并未验证其当前可用性。[S7]

不能为了启动旧认证而把旧整套 Agent 平台作为依赖。局部 Mock 身份可以用于开发测试，但不能作为正式登录验收。已有本地管理员入口可以做 smoke；无真实目标认证证据时标记对应验收未通过。

### 5.2 项目准备

维护者在环境外使用批准的只读连接取得选定项目和 commit，为不同用户建立独立可写副本。清除带密钥 remote URL、凭据 helper、子模块配置中的凭据等。记录 clean baseline；原始仓库不被修改。

V0 只支持明确选定的一类项目。依赖与测试命令从该项目决定，不先支持所有语言、GPU、桌面软件或浏览器自动化。

### 5.3 原生数据与恢复

先查看固定版本的实际数据路径，绑定独立持久卷，覆盖会话数据库/日志、原生快照或 blob 以及工作文件；不要仅持久化项目或只保存导出的聊天文本。

正常刷新、重登、空闲时容器重启要能重进同一会话。进程硬崩溃时可有未结算输出丢失或活动命令结束：必须如实显示中断/待确认，不承诺任意指令 exactly-once，也不自动重放最后一个任务。

原生存储保持唯一执行事实；平台健康、路由等状态不得反向假造 Agent 成功或失败。备份原生数据库必须保持一致性，优先对空闲且正常停止的实例做冷备，恢复演练不覆盖正在使用的数据。

### 5.4 结果取出

优先复用原生能力；不足时只加一个窄的、身份绑定的“下载变更”入口，不建设 Artifact 服务。

导出相对于记录基线的补丁，包含新增、修改、删除、已暂存和未暂存变化，必要时包含二进制；不能只用一条遗漏新文件的 diff 宣称完整。不得改写用户 Git 索引或自动提交。基线不匹配应明确失败。

遵守项目排除规则，不导出密钥、会话 DB、缓存、依赖目录或无关文件；对未跟踪的目标源码要按受控范围显式纳入。给出文件清单。用干净基线应用导出结果，再独立运行测试，证明用户拿到的成果可复用。

## 6. 输入与运维输出

下面是平台输入约定，不是 OpenCode 官方配置 schema。先发现并复用已有可用值，不在对话中展示秘密。

| 输入 | 来源与处理 |
|---|---|
| 固定 OpenCode tag/commit/制品摘要 | 起始候选见 UPSTREAM；实际校验后冻结 |
| 登录配置、两个试用身份 | 当前认证系统；只保存受控引用 |
| HTTPS 入口、试用主机与持久路径 | 已批准部署环境；无实际环境不得假称已上线 |
| 模型协议、地址、模型 ID、凭据引用 | 已有模型配置/网关；一个可用路由 |
| 项目来源、基线 commit、真实任务、验证命令 | 用户批准的项目/任务；缺少时明确阻塞 |
| 身份到实例的固定映射、资源限额 | 平台运维配置，普通用户不可改 |

实现方至少提供：可重复构建、启动、检查健康、原生和平台 smoke、浏览器验收、停止但保留数据、冷备与隔离恢复的真实命令。

配置模板中只有占位和说明；真正密钥不进入镜像构建层、Git、静态页面和日志。`doctor` 类检查应报告缺失项，不打印值。

## 7. 开发终点

当前切片通过 `ACCEPTANCE.md` 的必需项，真实用户按说明完成任务并签收后结束。下一条路径由试用反馈决定，不自动启动三阶段路线。

第二个身份的隔离测试是当前安全验收，不是扩展组织管理功能。常规部署说明、备份和失败提示也是交付条件，不是后台平台项目。

原生链路卡住就修原生链路；平台接入损失能力就修接入；外部条件缺失就如实报告。不得以新增模块、编写接口、追加测试数量来替代用户结果。

来源标签见 [UPSTREAM.md](UPSTREAM.md)。上述架构与范围是本次设计建议，不是 OpenCode 已提供所有企业托管能力的声明。
