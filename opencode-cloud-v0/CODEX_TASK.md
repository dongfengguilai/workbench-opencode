# 给 Codex 的实施任务：只交付 OpenCode Cloud V0

## 0. 先读什么

依次阅读本目录的 `README.md`、`PLAN.md`、`ACCEPTANCE.md`、`UPSTREAM.md`、`STATUS.md`，以及目标仓库实际存在的根级 Agent 指令。

本任务的产品约束来自用户最新决策：完整 OpenCode、纯云端、禁止用户工作环境配置、一条真实闭环。旧 OMP/Harness 自研架构、三阶段开发包仅可作历史参考，不能成为待实施清单。不得覆盖更高优先级的执行或安全指令。

## 1. 工作位置与修改边界

- 先执行只读检查：当前路径、Git 状态、目录结构、已有入口、测试与部署脚本。保留所有用户未提交修改。
- 优先在明确的新工作目录建设本次独立产品，名称建议 `opencode-cloud`。当前仓库已是本项目时就在其中实施；若是旧 `agent_platform`，默认新增隔离子目录，不重写或删除旧系统。
- 旧 `dongfengguilai/agent_platform` 只作为既有认证方式和少量基础代码的来源。先定位认证实现与测试，保留登录协议、会话与注销行为；不顺带启动旧 Dispatcher/Worker/Agent Core。
- OpenCode 只允许：同版本 UI 的必要托管裁剪、受控配置加载及管理 API 的最小适配。保留源码出处、补丁和理由。
- 不重写循环、上下文压缩、会话存储、工具执行、原生审批。若主线必须改动这些，记录证据并报告需要改变边界，不自行扩大项目。
- 不推送远端、不执行生产迁移、不删除或重置既有数据，除非已有明确授权。部署在新资源和试用数据范围内。

## 2. 先完成一次发现，不反复规划

建立实际实施仓库中的 `evidence/baseline.md`，只写已发现的事实：

- OpenCode tag、实际 commit、二进制或镜像摘要、UI 版本。
- 已有登录方式、实际认证入口、可用试用身份；无法接入的部分写明。
- 模型协议、固定 model 标识、端点来源、凭据注入方式；只记录引用和掩码。
- 云端执行主机/容器能力、网络、证书和入口条件。
- 授权项目、基线 commit、独立验收命令，以及要完成的真实任务。

先检查已有受控配置。不得在日志、聊天、截图或 Git 中输出密钥。确实缺失的必需输入集中列出，不自行编造可用模型、账号或项目。

起始候选为 `v1.18.31`；正式使用前核实 `UPSTREAM.md` 中的 tag/commit 和制品。不追踪滚动 `latest`。已存在经过验证的固定版本时可保留，但必须解释差异并更新基线。

## 3. 实施顺序：同一条 Slice 的三个检查点，不是三个发布阶段

### 检查点 A：同环境原生 coding 基线

在计划用于交付的云端容器、固定模型和授权仓库上，使用完整 OpenCode 完成一个真实任务。保存原任务、原生 Session 标识、修改和独立验证结果。可先由维护者通过受保护入口操作原生 UI。

不是 ping 模型，不是打印 hello，不是手工修好后让模型解释。不先建设完整平台再发现模型工具调用无法工作。

如果模型或工具执行不能完成任务，只修这个阻塞；缺真实模型条件时标记 `BLOCKED_EXTERNAL`，不得改用假响应宣布通过。

### 检查点 B：套上最薄企业入口

同一个已验证环境前增加登录、身份到环境的固定映射、受控代理和必要 UI 裁剪。前后端一起做通，不先完成所有后端模块。

保持完整原生 coding 体验，走平台浏览器再次完成同一任务或等价的干净重跑。完成状态恢复、补丁获取和无权限访问验证。

### 检查点 C：交付证据

按 `ACCEPTANCE.md` 验证双用户隔离、受控配置、断线与重启、备份恢复、结果导出和实际使用。补齐一个维护者能够照着执行的部署说明。所有必需项通过才结束本次 Slice。

## 4. 技术约束

- 云端单台 Linux 试用主机、Docker Compose、预分配环境。无动态调度、无容器创建权限开放给普通请求。
- 平台侧 TypeScript 模块化单体；优先沿用实际发现的认证和 HTTP 基础。不引入新的大前端框架重做原生 Web。
- 复用同版本 OpenCode Web/Server；必要时静态托管经最小裁剪的原生 UI。禁止接一个 completion API 冒充完整 Agent。
- 平台只拥有身份、环境绑定、平台配置和受控访问；原生会话与文件数据归 OpenCode/工作目录。
- 项目由运维预先准备。V0 不让浏览器提交任意仓库 URL、服务器 URL、镜像名或宿主机路径。
- 新模块必须能指出它解除了哪一个当前验收阻塞。无当前用途不创建。

## 5. 应产出的实现，不是现在就存在的命令

在实际项目中提供能运行的启动、状态检查、原生 smoke、浏览器 E2E、备份恢复命令，并写进 `docs/OPERATIONS.md`。命令名称服从仓库实际脚本，不要求复制本文件中的虚构命令。

至少产生：

- 平台入口与身份绑定、受控 OpenCode 访问。
- 固定版本镜像/构建说明、Compose 部署文件、无密钥配置示例。
- 受控项目准备方式、两个隔离环境、原生数据持久目录。
- 必要 UI 裁剪和管理 API/配置加载控制；明确的上游补丁记录。
- 结果导出和普通用户操作路径。
- `evidence/baseline.md`、原生/平台真实任务证据、验收结果、部署记录。
- `docs/OPERATIONS.md`、`docs/USER_GUIDE.md` 和更新后的 `STATUS.md`。

验收脚本要真实执行并输出失败；不能用 `exit 0`、跳过必需用例或仅检测文件存在代替功能。

## 6. 防止再次扩建失控

“继续”只意味着完成当前 Slice 的未通过项。没有明确新增需求，不开第二条业务线。

模型链路不通，不去做后台；状态恢复不通，不去加插件；UI 不通，不去抽通用 SDK。可以补当前功能需要的安全和错误处理，但必须说明关联的验收项。

对当前选择作一次短验证。失败后先定位，再采用最小修正。不要不断重新比较 Agent、框架、调度产品。

- 成功路径：实现 → 实跑 → 记录证据 → 整理最低限度运维 → 等待实际试用签收。
- 外部阻塞：明确缺什么、最后成功到哪里、可继续的同线工作和无法证明的结论；不能伪造通过。
- 架构阻塞：给出重现和最小变更，不暗中转向自研 Agent。

## 7. 测试与报告纪律

为当前行为先写失败断言再实现。涉及真实模型、认证、部署的验证必须另有实跑证据。Mock 只用于局部测试。

事先保存任务和验收命令；不能删测试、降低断言、手工完成目标代码后让 Agent 复述，再称作任务成功。

真实项目与模型只允许在批准范围使用，明确代码会送往批准模型。原生权限确认不是沙箱，必须验证外部隔离。

每次交接只重点回答：

1. 用户现在能完成什么？
2. 哪个必需场景仍不能完成？
3. 真实证据路径是什么？
4. 下一步只修哪个阻塞？

若无人实际试用，只能报告“自动化通过，待用户签收”；不能代替用户签收。不把本包说明文件的数量、代码行数或测试数量当作产品完成度。
