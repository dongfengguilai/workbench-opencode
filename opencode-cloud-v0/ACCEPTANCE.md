# V0 验收：用户能否完成一次真实工作

## 规则

以下是同一条 Slice 的 10 组必需验收，不是 10 个扩建模块。每组记录执行日期、部署/版本、数据基线、实际步骤、结果和证据路径。初始状态全部 `NOT_RUN`。

状态只能按证据填写：`NOT_RUN / PASS / FAIL / BLOCKED_EXTERNAL`。部署、模型、真实认证不能用 Mock 替代。脚本退出成功但存在必需跳过项，不算全通过。

先固定用户任务与独立验证命令。真实缺陷来自批准项目；若采用功能修改，应先定义可验证行为。人工注入的练习项目只算 smoke，不替代真实项目验收。

原生执行与平台执行使用相同基线、模型和规则，并在独立干净工作副本中完成，不把前一次修复直接带入第二次。保存所有尝试和人工介入，不只挑最好的一次展示。

## A01：目标环境中的原生 coding 基线

**步骤：**固定版本 OpenCode、真实批准模型、实际容器和项目；提出完整任务；由 OpenCode 读取相关文件、产生修改并执行项目测试。

**通过：**有真实 Session、工具活动、Diff 和退出码；独立验证目标行为正确。维护者没有提前修好目标代码，没有降低测试断言或删除测试。

**证据：**基线 commit、原任务、模型 ID（无密钥）、Session ID、测试前后输出、Diff、所有尝试及干预。无凭据或无法连接模型时本组阻塞，不能转去扩建。

## A02：真实登录到本人工作环境

**步骤：**从目标 HTTPS 入口使用实际支持的认证登录；点击已授权项目进入工作台；注销；尝试继续访问原 URL。

**通过：**不需要普通用户填写 Key/模型/服务器；映射到本人环境；注销和停用后不能继续发新请求或读取新数据；长连接按实现的有界再授权规则失效。无认证不能绕过代理直达实例。

**证据：**登录方式、操作录像/截图、网络检查、身份与环境映射的脱敏结果。开发 Mock 不算生产登录通过。

## A03：浏览器中的完整编码交互

**步骤：**由平台工作台重新执行 A01 的真实任务；进行至少一轮需求补充；实际触发一次受控提问或原生操作确认；执行一次明确的停止操作；继续正常工作。

**通过：**流式响应、工具过程和结果可见；用户回答/拒绝真实传到 Agent；停止不只是 UI 变色；必要终端/工具输出正常。没有以“只显示最终回答”削弱完整能力。

**证据：**浏览器实跑、原生状态查询、任务结果、操作日志。原生支持而平台丢失的关键交互必须修复，不改验收。

## A04：页面断连、重进与原生状态保存

**步骤：**分别在空闲和任务执行时刷新/关闭浏览器后重进；退出登录后再进入；空闲时正常重启环境。

**通过：**已保存会话和文件准确保留；不生成重复任务或重复消息；执行中状态以原生实例查询为准。短暂断连不能被误标为任务成功。恢复后旧流不覆盖新状态。

**证据：**同一会话 ID、文件摘要、重进前后状态、无重发的记录。不得拿导出的纯文本聊天替代原生可继续会话。

## A05：成果可取出且可复用

**步骤：**形成含新增、修改、删除和已暂存/未暂存代码的变更；下载补丁。在另一份固定 clean baseline 上应用补丁，独立运行验证。

**通过：**补丁覆盖工作成果，应用成功、测试通过；不改变原工作目录 Git 索引；不携带平台/模型/仓库密钥或会话数据；未授权用户不能下载。

**证据：**补丁摘要、文件清单、基线 commit、应用与测试日志。二进制或子模块等若选定项目涉及，必须明确支持或阻塞，不能静默遗漏。

## A06：两个身份的隔离

**步骤：**A、B 使用独立环境，在各自项目和会话放入不同标识。B 改写路由、目录/Header、Session ID、下载标识，尝试读取 A 的数据；从 B 的工作容器尝试访问 A 环境和宿主管理服务。还要在同一浏览器注销 A 后登录 B。

**通过：**服务端、网络、卷挂载均未越权；缓存不显示 A 的内容；实例端口没有公网直连；长连接不能沿用已失效授权；并发工作不互相写文件。

**证据：**实际拒绝结果与环境网络/挂载检查。A、B 测试数据与其他生产用户数据分开。测试不得获取无授权真实秘密。

## A07：平台配置确实不可由用户提升

**步骤：**普通用户尝试管理 UI、直接管理 API、消息体覆盖、项目 `opencode.json`/`.opencode` 新增 MCP 或插件，随后重新加载环境；在实例内尝试绕外层代理访问本机管理端点。

**通过：**平台规定的模型/工具/配置来源不被扩大；不加载未经批准扩展；没有泄露主 Key；普通任务仍能修改合法项目文件、执行受控命令。若需最小上游补丁，实际打补丁并回归，而非只写 TODO。

**证据：**原始和实际生效配置的脱敏对照、拒绝请求、未加载扩展的可验证结果、成功的正常 coding 回归。

注意：任务指令本身可自由表达，不把“用户不能配置环境”误实现成“用户不能提出要求”。管理员高优先级配置和只读目录不是本组全部证明。

## A08：故障时诚实，不盲目重试

**步骤：**模拟批准模型不可用、环境未就绪、请求回执丢失，以及用一次无危险外部副作用的任务测试进程中断。两次点击发送和第二个顶层写任务也要测试。

**通过：**明确报错、忙碌或结果待确认；不无限 loading；不静默改模型；不将超时标成功；不自动重复提交不确定任务；同一目录不出现失控的并发写任务。

**证据：**故障注入、原生状态、前端提示、恢复操作。不承诺崩溃前未结算 Token 或任意命令可无损续跑。

## A09：可部署、停机不丢数据、冷备可恢复

**步骤：**在目标试用主机按说明部署；停止后重新启动；在无活动任务时完成一致性冷备；将备份恢复到独立临时环境。

**通过：**命令真实存在；缺配置时明确退出；启动不覆盖工作；恢复后同一会话和项目成果可读取并继续。镜像/配置版本有记录，密钥受保护。

**证据：**实际命令、部署版本、备份摘要、恢复后的会话/文件校验。只生成 backup 脚本而未恢复不算通过。禁止默认 `down -v` 或覆盖现用卷。

## A10：真实用户签收与范围终结

**步骤：**用户不依赖开发者改后台数据，按使用说明从登录完成一次真实任务、检查和导出结果，再重新进入。

**通过：**用户明确确认该闭环可用于试用，且 A01–A09 均通过。必须记录残余限制：项目类型、模型、无本地访问、无远端写入、无通用恢复承诺。

**证据：**用户试用记录与明确签收。Agent 不得自动填写用户同意。未有人试用时，只能报告 `READY_FOR_USER_ACCEPTANCE`，不能写 `DELIVERED`。

## 发布判定

- `NOT_STARTED`：未实施。
- `IN_PROGRESS`：正在实现当前闭环。
- `BLOCKED_EXTERNAL`：缺少真实外部条件，写明受影响验收项。
- `READY_FOR_USER_ACCEPTANCE`：A01–A09 有真实通过证据，等待 A10。
- `DELIVERED`：A01–A10 通过并记录签收。

失败需要修复或明确调整交付约定；不删除失败用例来变绿，不降低现有安全边界来凑完成。

本包生成时没有执行以上任何软件验收。维护者填写本项目 [STATUS.md](STATUS.md)。
