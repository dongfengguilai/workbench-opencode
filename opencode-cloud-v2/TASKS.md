# 实施顺序：T0—T4

每个检查点使用“用户结果—修改范围—验收证据”签收；未通过不做下一批无关功能。必要的保护需随主线落地，不允许 T1 先放开危险入口、等 T3 再补。

## T0 · 冻结和测量，不研发监控平台

**结果：**知道当前真实任务能够完成，知道资源花在哪里。

记录实际代码/制品/配置摘要和宿主规格；只抽取已验收的一项代码修复、一项含终端或预览的代表性流程。采集平台常驻、单环境空闲、真实模型任务、构建/浏览器、停止后的资源；区分 RSS/cgroup/宿主页缓存/模型开销。区分用户磁盘逻辑长度与分配块。报告未知，不凑数字。

选定开发环境中的容量、观察时间和两个测试槽位；生产参数不照抄示例。确认 Docker namespace、防火墙、mount 与现有依赖顺序。定义按组启停受控名称集。

允许修改：资源采集小脚本、测试参数、基线记录。禁止建立监控大屏、全量重验 v1、换模型或重构。

验收：**V2-A01**。输出填写后的 [RESOURCE_REPORT](evidence/RESOURCE_REPORT.md)。报告完成立即转 T1。

## T1 · 一位用户完整的主动启停路径

**结果：**网页登录看空间不启动 OpenCode，进入后真实编码，主动安全停止，再进入继续。

一并修改页面、API、可信启停模块和固定部署入口。复用原生 UI、Session、配置及数据。新增空间首次初始化有标记且可恢复，已有空间绝不初始化。

停止入口先具备身份检查、操作屏障、原生任务/提问/PTY/后台进程核对及保护；忙碌拒绝并显示原因。明确未知进程不可回收。启动检查所有成员与防火墙，不能只测 native 端口 200。

验收：**V2-A02、V2-A03、V2-A08**，加 **V2-A06** 的基本忙碌保护。真实修改/测试/导出后重新进入，再做第二次修改。

禁止：等待全部管理功能完成才接前端；重做聊天与运行时。

## T2 · 有限资源供多人轮转

**结果：**三个空间争取两个名额，等待可见、可取消、不抢占正在工作的环境；模型总并发也有界。

先将 T1 的一空间锁扩展为同一单机控制器的名额与队列。排的是进入请求，不是用户提示词。重复进入去重、超时不冒充成功、UI 不盲重发；每个空间只允许运行一个有效代际。

基于现有网关集中可信模型入口，保持用户 scope 和计数，按后端执行总限制。所有原生辅助/子代理模型请求也计入。测试网关断线、取消、重启后的未知请求；不靠释放 HTTP 连接假定后端已停止。

验收：**V2-A04、V2-A05、V2-A10、V2-A11**。先用可控制后端 fixture 检查上限，再用批准的真实模型完成代表性工作。fixture 结果不得替代后者。

禁止：多节点、多队列产品、自动扩缩容；把所有 guard/出口共享化。

## T3 · 自动安全回收、恢复与容量保护

**结果：**明确安全的空闲环境会自动释放；活跃/待确认/状态不明的工作不被误杀。

自动停止调用 T1 的同一停止协议。加入有效活动记录、预览处理、终端和后台进程说明、停止竞争测试。控制器重启先锁定和核对容器，再恢复服务；自动启动策略不能绕开名额。网关队列/请求恢复不重放已派发内容。

新用户延迟初始化、配额/低磁盘保护、受控日志轮转；已有空间不迁移、不裁剪。禁用用户、未知状态、启动失败以及错误映射都要明确。

验收：**V2-A06、V2-A07、V2-A09、V2-A12、V2-A13**。故障注入只在授权隔离测试环境进行。

禁止：以“无法检测任何后台进程”为由把所有环境永久标成不能回收；同时也不能用最近 HTTP 请求时间盲杀。至少证明标准固定模板的正常空闲可回收，未知额外任务保守阻塞。

## T4 · 增量交付与停止扩建

**结果：**真实用户完成有限资源轮转与继续工作，收益由实测支持。

记录相同宿主、制品及任务下 v1 基线与 v2 的前后开销，说明残留开销、冷启动耗时和代价。不预设 90% 节省或百人容量。完成单机发布/回退演练，保持原数据、认证、证书、模型计数和已有功能。

验收：**V2-A14、V2-A15、V2-A16**，其余验收齐全。没有部署授权时交付待部署制品与真实开发环境结果；不得自动恢复退役服务器。

交付实际修改、经验证命令、资源报告、验收证据和真实签收。完成后停止，不添加 v3 清单充当本轮成果。
