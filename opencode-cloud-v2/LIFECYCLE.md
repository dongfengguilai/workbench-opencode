# 单机生命周期契约

以下是 v2 必须实现的行为，不是现有源码 API 说明。参考代码和 Docker 事实见 [SOURCES](SOURCES.md)。优先普通模块调用、单一写入者、受控本地存储；不要新建 Agent 工作流引擎。

## 1. 环境身份与持久数据

一个已授权空间绑定一个用户、固定项目、固定原生数据目录和环境组。每次启动有平台侧 `generation`；它只识别进程代际，不改变原生 Session 格式。

至少保留：空间标识、绑定版本、期望启停状态、观察到的组状态、代际/操作 ID、上次有效活动、正在进行的环境操作。名额事实和期望状态存储在 **常驻可信平台的数据目录**，不能放进待休眠空间，也不能成为第二份会话执行真相。

一个空间同时最多一个有效运行组。保留既有容器内 `/workspace/project` 等路径约定，外部路由不能由用户自填。

建议单写者采用现有可用的可靠存储方式；没有时可用很小的独立 SQLite 管理元数据。不得修改原生 OpenCode SQLite 表，不引入 PostgreSQL/Redis 集群作为本版前置。

## 2. 对外状态与内部名额

| 状态 | 含义 | 占运行名额 |
|---|---|---|
| UNINITIALIZED | 只登记空间，尚无重资源 | 否 |
| STOPPED | 已确认私有执行组停止，数据保留 | 否 |
| QUEUED | 一个有界的进入请求在等待 | 否 |
| STARTING | 名额已原子预留，正在初始化/启动/验证 | 是 |
| READY | 原生服务、guard、网络边界等均已验证 | 是 |
| DRAINING | 拒绝新工作，验证可停条件 | 是 |
| STOPPING | 已发送优雅退出，等待实际退出 | 是 |
| ERROR / UNKNOWN | 操作失败或事实不可知 | 若可能仍存活或预留未核对，保守占用 |

不能直接用 `status === READY` 计算占用。只有核对相关容器、子进程和未完成启动操作确已结束，才能释放名额。失败不代表资源已清理；磁盘初始化残留也不能自动删除。

实现可以用 `desiredState + observedState + lastError` 替代一张大枚举，但以上用户语义和不变量必须一致。

## 3. 入口行为

建议路由形状（可沿用现有命名，实施后在操作文档写实际路径）：

| 操作 | 行为 |
|---|---|
| GET 空间状态 | 鉴权后只读，绝不隐式创建、唤醒或续租 |
| POST 进入空间 | 空 body 或固定字段、CSRF/Origin 校验、幂等请求 ID；返回操作及明确状态 |
| POST 取消等待 | 仅本人队列项；多次调用幂等，不取消已经接受的 Agent 任务 |
| POST 停止空间 | 普通用户无 force；仅停止本人环境；忙碌返回原因 |
| 原生深链接 | 未 READY 时先进入轻量状态页，READY 后回到原链接 |

用户提交的内容不能包含宿主路径、容器名、镜像、命令、Node 地址或模型 Key。控制接口仅根据受信任绑定生成操作。

不得在进入队列里保存提示词，也不得在环境就绪后自动发送此前失败的原生请求。原生消息查证与重发规则保持已有实现。

所有状态页可用性应独立于用户执行组：平台启动不能依赖每个 native-guard healthy，`/__platform/me` 等也不能在空间停止时只有 503。

## 4. 名额与等待

单一控制器持有单机管理锁；使用受控持久预留避免并发双启动。在执行 Docker 操作前预留名额。只在同一空间锁内改变代际，其他请求取得同一个进行中的操作。

等待队列以空间去重，FIFO 即可，不做优先级产品。只允许活跃授权主体等待，设最大项数、到期时间和显式取消。等待项可以被写入平台元数据，但不代表任务被接受。控制器重启后先展示旧等待项为“需要重新确认”；用户确认后重新进入，不自行恢复自动派发。

若取消发生在启动已开始之后，不声称已经未启动：返回实际 STARTING 状态；启动完成后仅在确认安全时停止未使用环境。最终用户能理解结果，预留不能重复释放。

即使名额有空，若磁盘余量不足或资源状态未知，也拒绝启动。调低上限时不驱逐正在工作的环境；停止新的准入，等待数量自然下降。

## 5. 启动顺序

1. 鉴权、确认用户启用、读取固定绑定、预留名额及代际。
2. 检查已有数据及挂载。新空间用受控临时区初始化并写标记；已有空间只验证，缺数据则报错，不建空空间冒充恢复。
3. 启动必要的私有成员。先建立受控网络和访问边界，再开放任何可以执行用户代码的路径。
4. 验证原生二进制/配置、guard、持久挂载和健康信号。共享模型网关不可用时显示原因，不把基础进程存在当作 READY。
5. READY 后才允许浏览器原生请求、PTY、预览和 Agent 工作。

注意参考 Compose 中 `network_mode: service:native`、不同 UID 和防火墙规则的依赖：native 重建后 guard 可能指向旧 namespace。启动/恢复必须重新检查相关成员，不能只执行一个 `docker start native`。

原生服务可能加载持久状态；必须验证固定版本启动不会在安全边界未就绪时自动派发旧工作。本版不实现任意任务的自动恢复。

失败后保留诊断和用户数据。自动清理仅限确知由本次失败启动新建的计算对象，不删除有既存标记的卷，不无限尝试。

## 6. 安全停止协议

### 6.1 先检查，再锁住新入口，最后复查

预检查发现任务/提问/终端等阻塞时，直接返回明确原因，保持原有工作不中断。初步安全时，在同一空间锁中建立 DRAINING 屏障，然后复查，以消除刚检查空闲就有新请求进入的竞争。

屏障必须覆盖原生 prompt/shell/command、PTY 创建和已有 WebSocket 输入、平台预览启动、导出/恢复等入口；只挡“发送消息”按钮不够。已有数据/事件读取是否能继续由同一代际处理，不能流入新的实例。

并非所有写入都来自 HTTP：已经启动的子进程可继续工作。因此必须同时检查原生状态、问题/审批、平台受保护操作，以及本环境 cgroup/进程树中的工作进程。

发现竞态或未知进程时撤销本次停止屏障，回到可工作状态并解释；不要为了释放名额先发送退出信号。

### 6.2 哪些情况禁止自动停止

- 原生任务或模型请求仍在进行，包含等待容量的原生请求。
- 原生审批/问题等待回答。
- 构建、测试、导出、备份、恢复仍在执行。
- 用户终端仍有活动任务，或出现不能证明安全的子进程/后台服务。
- 任何状态观测失败、超时或不一致。

原生 `/session/status` 是一个信号，不是所有后台工作的证明。不能仅以“HTTP 一段时间没请求”或“CPU 很低”判断可停。

### 6.3 标准模板必须真的能自动回收

T0 列出固定版本平台/原生后台进程和可重建服务，如 LSP、标准预览。只对明确由平台管理且无活跃任务的这些对象定义安全结束方式。用户自定义后台任务一律显示阻塞，不默认 kill。

标准预览只有在平台定义的无有效使用时间到达后才能结束；停止后 UI 写明再次进入需重新启动。用户仅查看代码可通过真实键鼠/可见交互等低频活动信号保持活跃；不传键入内容。SSE 心跳、健康检查、文件轮询、预览 HMR 心跳、后台标签页定时器不得刷新有效活动。客户端活动只证明使用意图，不能覆盖服务端的忙碌/未知事实。

参数样例见 [resource-policy](examples/resource-policy.example.json)，不是生产建议值。没有可靠时间历史或系统时间突变时保守重新等待一个空闲窗口，不立即回收。

### 6.4 优雅退出不等于默认 Docker stop

发送经固定版本验证的优雅退出信号并观察。Docker 默认 stop 超时会 SIGKILL [S5]；本版自动回收不得在观察超时后自动强杀。

可使用无强杀的信号/等待方式，或验证过的无限 grace stop 并由控制器单独有界观察。观察超时后标记 ERROR/停止待确认，保留名额和数据；不能把终止客户端等待当作取消了 daemon 中的 stop。强制结束仅属于独立运维事故处理，需明确授权，不提供给普通进入队列的自动逻辑。

整个私有执行组确认退出后才发布 STOPPED、撤销旧预览/原生连接代际并释放名额。持久数据、平台登录身份和用量不清零。

## 7. 恢复与重启

常驻控制模块启动先取得唯一管理锁、读持久记录、检查实际 Docker/mount 状态，再开启新准入。已有运行环境保持保守占位；孤儿预留只有在确认无进程、无进行中的启动后释放。异常记录不驱动旧编码任务重新发送。

建议用户执行组明确由生命周期控制器负责启动，避免 Docker `always/unless-stopped` 与另一管理器冲突 [S6]；采用 `restart: no` 或等价单一所有权配置时，原生异常退出应显示可恢复错误，不自动重跑任务。共享平台服务可以保留受控自动恢复。

重启宿主/Docker daemon 后不得整体 `up` 所有空间。无法确认底层状态就停止新准入，不把计数当 0。

再次进入验证逻辑会话、用户文件、Git HEAD/索引/未提交修改和成果。SQLite 文件哈希可因正常 checkpoint 变化；应比较逻辑内容和完整性，不要求活数据库字节恒定。

## 8. 隔离和权限

Docker helper 只接受已登记空间标识和白名单动作，通过本机 Unix socket/固定子命令等受保护通道调用；不提供任意 Shell、任意 mounts、任意 images。进程组/文件操作只触及本产品标记，不能全机扫描并杀死“看起来空闲”的服务。

不同用户的数据、原生凭据、出口权限和资源状态继续隔离。当前 Cookie/Origin 实现沿用已验收方式，不借按需化重做认证；停用/注销必须撤销新控制请求与队列项。停止和注销是两种不同动作。
