# v2 增量验收

## 总口径

v0/v1 完成结果继承，以下只检验 v2 新行为及被影响的旧能力。不是要求再次执行全部旧矩阵。

`fixture` = 可控模拟依赖的规则验证；`live_runtime` = 真正启动本版及完整原生环境；`live_model` = 经批准的真实模型完成原生工具任务；`measurement` = 可重复的实际资源测量。多种类型不能互相冒充。

记录每组的环境、制品、命令/操作、结果、证据摘要、未通过子项。任一必须子项失败，该组不能 PASS。真实后端不支持的能力要记录限制并采用安全退化，不得假设支持。无法在批准环境测试的写 BLOCKED_EXTERNAL，不写成功。

本包没有应用测试实现。Codex 要在现有测试体系中实现下述场景，不能把包检查脚本当作完成标准。

## V2-A01 · 资源与工作基线

固定实际 HEAD、原生版本、UI/镜像/配置摘要、宿主 CPU/RAM/可用磁盘与同机模型开销。测一个已验收真实任务及包含构建/浏览器的代表性流程，不以模型 ping 代替。

分开记录常驻平台、执行组空闲/工作峰值/停止后的开销，明确统计口径和不能归属的共享项。区分逻辑磁盘容量、宿主分配块、共享镜像、实际数据与备份。填写 [资源报告](evidence/RESOURCE_REPORT.md)，选择有依据的测试参数，不预设生产人数。

必须证据：measurement。

## V2-A02 · 登录不唤醒与延迟初始化

在所有用户执行组停止时，真实登录/查状态/健康检查/原生深链接均不会启动 OpenCode。明确点击进入才产生启动。

新用户只登记元数据，不立即创建整份配额镜像或运行组；第一次进入初始化一次。中途失败保留可识别状态，再试不覆盖已有数据。已有空间缺数据/标记不匹配时拒绝“自动修复”。

必须证据：live_runtime；附动作前后 Docker 状态及目录变化，不只截图。

## V2-A03 · 主动启停及真实编码闭环

A 点击进入，检查所有环境成员和边界就绪后进入原生 UI。完成真实代码修改、测试、Diff、既有成果下载；显式停止并确认组退出；再次进入同一空间，找到原会话并继续第二次修改和测试。

STOPPED 时不能仍有 native、guard、私有出口或遗留浏览器等被漏记；不可停的轻量入口明确列为常驻开销，不混淆。主流程不能依赖开发者手工修数据库或启动容器。

必须证据：live_model。

## V2-A04 · 重复进入与启动边界

同一用户双标签页并发进入、重复请求 ID 和快速重连，只创建一个有效代际、只占一个名额。模拟 guard/防火墙健康失败或 namespace 更新，READY 必须等待全部验证。

没有安全边界的 native 不能处理用户任务。启动失败而仍残存进程时保守占位；真正清理完才释放。首次初始化的源码/索引不被重复初始化破坏。

必须证据：live_runtime。

## V2-A05 · 有限名额与进入队列

三空间/两名额：A/B 已占位，C 等待；多次点击 C 不重复排队。等待可取消、有界、有最大等待，服务端不保存提示词和自动提交任务。

启动中/停止中/可能存活的 UNKNOWN 也占名额；队列满明确反馈；正在工作用户不被驱逐。A 完成并安全停止后 C 才获得名额。启动中取消不能提前释放被占名额或创建重复组。

必须证据：live_runtime；含时间序列和实际运行容器数。

## V2-A06 · 安全停止与竞争

分别在真实 Agent 生成、测试进程、待回答问题/审批、导出、终端工作及未知后台进程存在时请求停止，均不得误杀或丢数据，显示具体阻塞。

并发启动任务与停止请求，DRAINING 屏障和复查必须避免“检查后新写入”。包括已有 PTY WebSocket 输入和平台预览启动，不只 HTTP prompt。

在隔离测试进程中模拟不响应优雅退出，观察超时不会自动 SIGKILL，状态为错误/未知且仍占名额。用户停止不会删空间、清计数或注销账号。普通用户没有 force 参数。

必须证据：live_runtime。

## V2-A07 · 自动回收与有效活动

测试用短时间参数下，固定模板正常空闲确实自动停止并测到资源释放。只有 SSE 心跳、健康轮询、HMR 心跳、隐藏标签页计时，不能一直续活。

真实阅读/编辑的有效活动可续活；活跃任务、待确认、后台服务和失败观测优先阻止回收。用户自定义未知进程不自动杀；平台受控预览按明确规则关闭并提示重启。服务端时钟变化/重启不让环境突然被误判超时。

必须证据：live_runtime。既要证明“该停会停”，也要证明“不该停不会停”。

## V2-A08 · 原地继续与数据保持

正常停止/再次进入后比较会话逻辑内容、项目源码、Git HEAD/索引/未提交改动与成果。原生 SQLite 检查完整性，允许正常 checkpoint 引起文件字节变化。

旧连接/票据不误指向新代际；浏览器不重发旧提示词；原终端/预览/浏览器进程若已退出，如实显示需重新启动，不伪装活着。原生续用按固定版本支持范围，不承诺任意中断工具自动续跑。

必须证据：live_runtime。

## V2-A09 · 控制器与Docker恢复

在 STARTING/READY/STOPPING/QUEUED 状态分别重启测试控制器；单一管理锁、持久预留及实际进程核对有效。READY 工作不因单纯控制器重启被重发或强杀。

在专用测试 daemon/宿主验证 restart policy 不整体拉起全部用户组。旧队列要求重新确认而非自动发送；旧未结束组保守占位；孤儿预留只在确认无运行/启动后释放。无隔离演练条件则报告阻塞，不重启共享生产 Docker。

必须证据：live_runtime。

## V2-A10 · 模型总并发与身份用量

可控后端精确记录同时执行数，验证多用户、辅助调用、同后端不同模型别名都受同一上限；每用户上限及公平短队列生效。

队列满/等超时明确返回，原生不无限重试；队列等待低于真实全链路请求截止时间。用户不能改请求体借用别人额度或直连模型后端。旧日计数按身份继承，重登/停机/重启不归零。

再用批准的真实模型完成真实 OpenCode 工具任务，流式、工具调用、正常错误呈现不退化。

必须证据：fixture + live_model。

## V2-A11 · 模型取消与未知后端状态

排队取消不派发；派发后取消尝试中止上游；重复 close/end 事件只释放一次。故意让 fixture 的客户端已断连但后端仍计算：不得立即释放导致总执行数超限。

重启网关时，对已派发但未确认结束的请求保守恢复容量；不能清 0 或重发。真实后端没有取消/状态能力时，验证 UNKNOWN 暂停新准入和维护恢复路径；本地 timeout 不能冒充后端硬截止。

网关产生未决请求时环境不能被自动误判空闲。真实后端支持/不支持的取消与截止语义必须单独写明，不要求不存在的能力、不虚构回执。

必须证据：fixture + live_runtime（含真实配置与实际 UNKNOWN/drain 行为）；不声称模拟测试验证了真实 GPU 取消。

## V2-A12 · 隔离与访问控制

A 不能读取/启动/停止 B 空间、取消 B 等待、获取 B 状态细节或借用模型 scope；改变路由 ID/用户头/请求 body 不生效。

注销/停用后不能发新控制请求，旧等待撤销；WebSocket、预览和下载沿用既有身份边界。共享网关没有把私有网络并成互通网，工作容器无 Docker 管理权、主 Key、任意上游 URL 或凭据写入口。

必须证据：live_runtime。无关旧验收无需重做，变更触及的边界必须实际验证。

## V2-A13 · 磁盘与日志容量保护

空间不足前拒绝新初始化或唤醒，不能创建不完整空间后标 READY。保留原有配额，真实数据不删不裁剪；只清理平台明确拥有的临时文件与轮转日志。

在隔离限额文件系统中实际模拟写满；显示错误、保留已有数据、恢复后核对原生完整性。另用 fixture 验证临界分配与并发准入。不能填满真实宿主/同机模型盘，也不能把文件名为 db/state 的源码列入清理。

必须证据：fixture + live_runtime。

## V2-A14 · 资源收益与冷启动代价

相同环境对比 v1/T0 与 v2：启动前、空闲就绪、任务峰值、停止后、再进入；记录私有组内存/进程/CPU、总开销、共享模型背景与冷启动耗时。

登记多个未进入空间，验证不会增长整套常驻执行负载及新建重磁盘镜像。合法持久数据仍随真实使用增长，不宣传零存储开销。

私有组确认停止后没有该组进程；宿主缓存不必瞬间清零。明确残留入口服务及成本，不把组件变名或进程迁移成“节省”。不预设节省比例，记录实际收益和启动等待代价。

必须证据：measurement，填写资源报告真实表格。

## V2-A15 · 增量发布及回退演练

在授权测试栈验证从当前实际基线到 v2 的配置/重启策略/网关计数迁移；原有会话、源码、计数、凭据、证书和入口不重置。

回退保留新增工作和最新计数，不能用旧数据覆盖；只启动明确允许组，避免旧整体启动脚本突破名额。制品和状态格式不兼容时明确拒绝。

真实部署只在明确授权目标进行，无授权最高 READY_FOR_DEPLOYMENT。故障演练不得操作退役服务器或同机其他业务。

必须证据：live_runtime（至少真实测试栈升级/回退；线上部署证据另记）。

## V2-A16 · 三个空间两个名额交付

一条连贯用户流程：A/B 实际工作，C 等待；A 安全停止并确认资源释放；C 获得名额完成真实任务；A 再进入继续原会话与未提交修改，测试并导出成果，在干净副本复现。

使用既有真实身份完成代表性交互；模拟身份用于容量规模测试时必须注明，不冒充三次真实 NetID。真实用户无需维护者临时补数据库或手工拉容器即可完成。

记录制品/任务/会话、入场顺序、真实工作结果与资源事实。技术验证不能代填用户签收；明确由真实用户完成本版路径后，记录用户确认的来源。

必须证据：live_model。最终签收还需要 `humanAcceptance` 和获准目标的 `deployment` 记录。

## 记录与验收检查器

在 [acceptance.json](evidence/acceptance.json) 中登记。证据可以是脱敏日志、JSON、截图说明和外部审核记录的受控引用；检查脚本要求用于检查的脱敏文件复制到包内 `evidence/`，并记录 SHA-256。不复制秘密和私有冷备。

`check_release.py` 只能检验记录齐全、证据文件存在且摘要吻合，不能证明证据真实，也不能替用户签收。伪造一个 PASS 文件不符合验收；禁止由开发 Agent 为通过检查而制造“真实用户已确认”。
