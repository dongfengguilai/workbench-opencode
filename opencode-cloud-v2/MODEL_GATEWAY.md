# 共享模型网关：有限改造，不建设模型平台

## 1. 唯一目的

同一单机部署中的所有用户环境，通过一个受信任网关访问已批准的模型后端。沿用现有 `model-gateway.ts` 的流式转发和模型白名单，增加身份隔离、总并发及正确的请求生命周期。

当前参考代码的 `active` 是进程内变量、凭证是单 `ENV_MODEL_TOKEN` [S4]。多个这种进程不能被当作一个全局上限。本版不引入高可用副本；若有其他系统同时使用同一后端，其负载属于 T0 的容量背景，不宣称能管理未接入网关的所有请求。

## 2. 控制项

- 环境 token 由可信配置映射到用户/空间和允许的模型，浏览器不得传入任意目标地址。一个用户不能通过自报 userId 消耗别人的预算。
- 实际限制按 `backendCapacityKey` 归并；两个模型别名若共用同一推理服务，要共用容量，不按显示名称分别放满。
- 分别配置全局在途上限、每用户在途上限、有限队列长度和最大等待。
- 队列简单公平，防止单用户占满；不建设分布式优先级调度。
- 正常模型响应、工具调用和流式内容透明传递；不更换模型、不自动 fallback，不为排队修改 Agent 循环。
- 计数包括 title/compaction/子代理等辅助模型调用。工作空间停机不能重置当日用量。

生产值来自 T0；示例配置只用于测试。每个运行环境允许工作，不代表每个环境同时可以获得模型请求槽位。

## 3. 流程和回执

```text
认证及请求大小/模型约束
        ↓
申请用户与后端名额；不足时短暂有界等待
        ↓
取得名额并记录派发意图、用量预留
        ↓
仅发送一次上游请求
        ↓
原样转发流式结果
        ↓
确定结束后释放；不确定则隔离待核对
```

队列只在当前连接内等待，不返回 OpenCode 不识别的异步 taskId。超时和超额采用固定版本已验证、不会引发无限自动重试的错误语义。不能随意换成 429/5xx 后宣称“不重试”，必须实测原生行为。保留旧实现失败信息语义和用户可理解提示。

队列最长等待必须小于原生、平台、guard 和上游相关请求截止时间的可用余量。基线中的多个超时不同；实施前列出实际值，不增加长队列让原生先超时。排队和派发中的请求必须成为环境停止的阻塞信号。

## 4. 请求取消和未知结果

**客户端连接关闭，不证明后端 GPU 工作已经结束。**不能仅在浏览器断连或 `res.close` 时无条件把并发数减回去，再立即放入新请求。

建议在可信网关自有小型持久状态中记录 requestId、身份、后端、派发时间及 lease 状态。不保存提示词内容，不作为任务编排日志。

| 情况 | 处理 |
|---|---|
| 排队中取消 | 移除队列项；没有上游派发，不占用真实执行槽位 |
| 明确正常结束 | 记录结束，一次性释放槽位 |
| 派发后客户端取消 | 向上游取消；释放必须依赖已验证的后端结束语义 |
| 网络中断/网关崩溃 | 已派发但不能证明结束的请求为 uncertain；保守保留对应容量 |
| 上游有可信状态或取消回执 | 查询/确认结束后释放 |
| 无法确认后端结束 | 仅可依据后端实际强制执行且已验证的硬截止时间释放；本地 HTTP timeout 不算 |
| 无状态接口、无可信硬截止 | 暂停对应后端新准入，显示维护核对所需条件；不凭经验延时后假装空闲 |

冷启动网关先核对旧请求记录和真实后端状态，再放行；不清空 active 后重放。可以在受控后端 fixture 测取消/超时，但真实后端取消或 drain 能力也需要单独验证或明确报告限制。

本版不保证多次调用的业务 exactly-once；网关只转发当前模型请求一次，不重放已发送且结果不明的请求。

## 5. 用量和凭据迁移

新共享网关不能把旧两个用户的 `budget.json` 随意合并或清零。停准入并等待请求收敛，在变更前后核对每个环境的日期/计数；映射不确定就停止迁移。原有按 UTC 日、失败已派发请求计数等约定保持并写明。

排队后取消/未派发不应新增派发次数；实际一旦预留并派发，未知请求按保守已消耗处理。计数更新原子化，损坏时拒绝新派发而不是从 0 开始。

主模型凭据只在共享可信网关；空间持有自己的 scope，不含全局管理权限。scope 失窃仍受身份、模型和资源上限约束。

共享网关不能让所有私有环境被连到同一个可互访的网络中。沿用逐环境内网或明确 ACL，工作负载只能到授权网关/出口，不能直接到推理服务或其他用户。共享服务不能提供通用 URL 转发或流量路由功能。

## 6. 最小验收

[V2-A10 / V2-A11](ACCEPTANCE.md) 要覆盖两用户争用、同后端别名合并、辅助调用、队列满/超时、取消、后端未取消、网关重启、重复结束事件、权限绕过和用量不重置。先检查并发逻辑，再让批准的真实模型完成原生代码任务，不用 Mock 取代真实效果。
