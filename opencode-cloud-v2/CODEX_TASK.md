# Codex 实施指令 · v2

## 任务

在现有 `dongfengguilai/workbench-opencode` 上增量实现 **单机按需工作空间**。交付同一条用户闭环：

> 登录查看空间不启动 Agent；明确进入后申请运行名额；工作时使用完整 OpenCode；主动或安全空闲停止后释放私有运行资源；重新进入继续原会话与项目。

v0/v1 已由用户确认完成，直接继承。不要只写方案、演示静态页面或扩写文档；需要实际实现、启动允许的开发部署并验证。

## 阅读顺序

[BASELINE](BASELINE.md) → [PLAN](PLAN.md) → [TASKS](TASKS.md) → [LIFECYCLE](LIFECYCLE.md) → [MODEL_GATEWAY](MODEL_GATEWAY.md) → [ACCEPTANCE](ACCEPTANCE.md) → [OPERATIONS](OPERATIONS.md)。

发现仓库根有效 `AGENTS.md` 时也必须读取；本包不覆盖它。

## 首轮必须做的事

1. 记录实际 HEAD、工作区修改、固定制品与部署位置；保护用户未提交文件。
2. 根据现有代码核对环境组成员、网络命名空间、重启策略、原生 API、备份和凭据范围。不要把参考提交当成目标机的绝对真相。
3. 在已授权开发环境完成 T0 的最小资源基线，选定既有真实编码任务作为回归；不要重跑全部旧验收。
4. 立即推进 T1 的前后端闭环；不先单独建完调度、存储、网关或管理后台。
5. 每个新增行为先建立会失败的测试/验收，再实现，并保存真实结果。

本包内没有应用实现代码，也没有已经存在的生命周期启动命令。文档中的新增 API 是契约建议；你必须将它落实到实际接口、测试和使用说明，不能引用不存在的命令声称已运行。

## 冻结范围

允许：原有入口增加空间状态；可信单机环境启停模块；有限队列与名额；现有模型网关的多身份与总并发；配额/空间报告/低空间保护；必要的部署和回退适配。

禁止：升级 OpenCode；重写循环/上下文/工具/会话数据库；多用户共享一个原生进程；多机调度、迁移、共享文件系统；Agent 能力实验；多项目协作；动态插件系统；新建通用 Runtime；用户环境配置；自动 PR；本地连接器；无关 UI 改版。

确有原生缺陷阻断本条主线时，只做证据支持的最小修补并说明；不能借此升级或整体重构。

## 变更与权限纪律

- 仅修改当前切片需要的文件。可以整理实际重复，不进行全库格式化或“大清理”。
- 不因 v2 编号改名旧目录/Compose/数据卷；不 reset、不重建现存用户空间。
- 默认只在开发环境操作。退役服务器、同机模型和其他业务没有新的明确授权就不动。
- 不运行全局 Docker prune、不关闭 TLS 校验、不绕过 guard、不把 Docker Socket 或管理凭据交给工作负载。
- 资源配置由管理员决定；浏览器提交的空间 ID 必须鉴权，不能接受容器名、主机路径、命令或上游 URL。
- 密码、令牌、私钥、代码敏感片段不得进入公共日志和证据。请使用摘要和脱敏引用。
- 停止/重启测试在隔离测试栈进行，不通过杀死真实用户任务验证保护。

## 执行节奏

一次只承诺 TASKS 中当前检查点。用户说“继续”，默认继续解决其未通过项，不扩展新功能。

外部条件缺失：先从仓库和受控环境发现已有配置，不重复询问已知内容；无法解决时准确报告缺哪个条件、已完成什么及哪里未测。Mock 可验证内部规则，不能冒充真实模型、真实环境或用户签收。

如果测试表明设计需要微调，选择最小、可回退的解决方式。不得自行降低验收、关闭安全检查或用“暂不支持”删除本版主功能。

## 最终交付

实际代码与增量提交说明、可重复构建制品、经验证的部署/回退命令、16 组增量验收、资源前后对比、真实用户签收。

未部署到获准目标时最高为 `READY_FOR_DEPLOYMENT`；技术验收全部完成而未签收时最高为 `READY_FOR_USER_ACCEPTANCE`；只有真实用户完成本版路径后为 `DELIVERED`。不自动进入 v3。
