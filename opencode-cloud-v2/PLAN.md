# v2 方案：单机按需工作空间

## 1. 唯一产品增量

从“开通用户便长期运行整套服务”改为“独立空间长期保存，实际使用才占用运行资源”。用户仍使用完整 OpenCode，不共享项目或原生进程。

签收路径：三个独立空间、两个运行名额；A/B 工作，C 等待；A 完成并安全停止，C 进入；A 再次进入继续原来的真实工作，成果可复现。测试参数不等于生产容量承诺。

## 2. 结构与所有权

```text
常驻可信平台
  登录/授权 + 轻量空间页 + 固定入口
  单机生命周期管理 + 共享可信模型网关
                    |
     ┌──────────────┼──────────────┐
  空间 A          空间 B          空间 C
  私有数据        私有数据        私有数据
  按需执行组      按需执行组      按需执行组
```

平台保留模块化单体。Docker 控制操作可以是单独受保护的宿主 helper，它是权限边界，不是要建设分布式调度服务。默认一个可信生命周期写入者；并发启动不能跨过同一把持久名额锁。

环境状态、名额和期望状态属于平台；编码任务、工具、审批内容和原生会话属于 OpenCode。允许少量环境操作记录，不允许新的平台 RunCoordinator 驱动 Agent。

持久空间包括源码、Git 元数据、原生会话及必要状态。停止不删除或初始化这些数据。临时进程内存、终端和预览进程不保证恢复。

## 3. 实现范围

| 能力 | v2 必须实现 |
|---|---|
| 轻量入口 | 登录、看状态不唤醒；进入按钮才请求启动；原生深链接先过状态页 |
| 按需执行 | 以现有固定身份和项目绑定启动完整环境组；完整原生交互保留 |
| 安全停止 | 先主动停止闭环，再同规则自动回收安全空闲；未知状态不强杀 |
| 容量 | 全机环境名额、有界去重等待、取消和失败反馈 |
| 模型 | 基于现有 gateway 建立单节点共享入口，按凭证识别身份及用量，总并发有界 |
| 空间 | 新用户延迟初始化；已有用户不迁移；实占与配额区分；低空间保护 |
| 持续使用 | 重进和控制进程重启后不重复运行、不双写、不重放历史任务 |

## 4. 不做清单

不升级 OpenCode，不提高“智能程度”，不增加更多工具；不合并用户的 OpenCode；不做多机放置/迁移/高可用；不换文件系统、不裁剪旧磁盘镜像；不建设插件、调度或评测平台；不增加多项目协作、自动提交 PR、用户配置或本地访问。

不要求休眠时浏览全部原生历史：先唤醒再看。不要为了休眠列表另建会话投影和查询系统。

## 5. 空间/运行/身份三种操作分离

“停止环境”释放工作进程；“注销”撤销浏览器授权；“删除空间”不在本版。退出网页/注销不会自动取消进行中的任务；后台安全回收按服务端事实执行。

用户无权限或被停用时不能获得新名额/模型派发；已有任务按现有策略明确处理，不静默删除、不声称未知任务已完成。

## 6. 小范围代码影响

以实际 HEAD 为准，以下是参考定位，不是必须创建同名新文件：

| 现有位置 | 所需变化 |
|---|---|
| `src/platform.ts` 与现有 UI | 空间状态/进入/停止/等待；用户绑定鉴权；不重写原生聊天 |
| `src/native-proxy.ts`、`environment-guard.ts` | 启停入口屏障、忙碌判断与重连；旧消息不自动重发 |
| `scripts/v1-deploy.py`、Compose | 平台启动与逐环境启动分开，明确资源所有权、重启顺序和恢复 |
| `src/model-gateway.ts` | 多身份凭证、共享后端总并发、取消与计数迁移 |
| 原有 `test/` 与部署测试 | 从真实业务路径补增量测试，参数仅为消除本次真实重复 |

历史代码有整体 `compose up` 和逐进程模型计数 [S3/S4]，不可只在 UI 中加“休眠”按钮假装资源已回收。

## 7. 资源策略

T0 测出环境组基础与峰值开销，选择 `maxRunningEnvironments`。保留平台、同机模型和其他业务的预算；不把容器内存上限当作实测 RSS，不把空闲值当作峰值。

不同环境组若资源预算不同，本版采用保守统一预算，不引入复杂权重调度。启动中、停止中和状态不明但可能存活的组都占用名额。私有边缘代理等若无法在首轮停掉，需要列为残留开销，明确测量和上限，不能隐瞒为“零占用”。

磁盘采用原方式和配额。新用户可延迟创建重资源；不得为了节省空间截断/重格式化旧镜像。统计共享镜像、实际分配、逻辑配额、用户数据、日志与备份，避免重复相加 [S7]。
