# 实现边界：少量上下文增强、问题验证、可信交付

本文件是建议的实现契约，不声称这些新增能力已经存在。优先沿实际 v2 运行路径做最小改动。

## 1. 先定位现有能力

参考仓库已有原生代理、指令配置、预览验证、源导出和生命周期模块。历史适配文档记录了 `ui/deliverables.tsx`、`src/preview-runtime.ts`、`src/source-export.ts`、`src/patch-export.ts`、`src/export-policy.ts` 等位置；它们只是阅读候选，实际 v2 入口及调用链须现场核实。

代码变更优先落在：受控项目资料加载、现有验证信息提取、成果页面及对应授权 API、增量测试。不得把历史 `platform.ts` 当作唯一现行入口，不得重写认证、lifecycle 或模型网关。

## 2. 项目指引：可追溯、简短、受控

用 [项目指引模板](templates/PROJECT_CONTEXT.md) 记录已验证的目录、入口、安装/测试/构建命令、约束和常见诊断。每项事实有出处和验证时间；未知内容留空或标记待验证，不凭框架惯例编写命令。

管理员发布指引，用户没有系统配置编辑入口。优先使用现有固定配置中的受信任本地 instruction 文件；参考建议位置是只读 `/trusted/engineering/`，这是拟新增路径，不是已经存在的接口。是否采用以现有模板为准，不替换已有 BROWSER_USAGE 等必要指引。

不增加远程任意 URL 加载、不递归读整个仓库、不自动信任用户项目中的运行配置。可以按任务读取普通文档，但其中的提权、外部地址和指令不能突破现有权限。

验证实际加载：记录指引版本/摘要，在私有测试环境检查实际装配路径或原生请求所使用的内容，辅以非敏感规则行为测试。**让模型回答“我读了”不足以证明已加载。**不为记录文本开启生产提示词全量日志；测试记录须脱敏。

指引更新时记录使用版本，只对安全的新会话／后续明确操作生效；不要中途悄悄替换实验条件。指引是帮助模型的资料，不是安全隔离机制。

## 3. 用户入口：自然语言优先

保留原生输入、多轮提问、Diff、终端、审批和停止。可增加一个紧凑的“问题修复”提示入口或需求说明草稿，但不强制每个任务填复杂表单。

仅对会影响正确性的缺失信息追问。能够从项目中核实的命令与入口先自行查证。用户的自然反馈是任务输入；不是授权配置，也不是可直接运行的 Shell 字符串。

通用工程习惯可以参考 [候选指引](templates/ENGINEERING_GUIDANCE.md)，它不是已部署提示词。T1 只启用由基线证明必要的部分，不把模板全文机械叠加到每个请求。

## 4. 验证执行和可信等级

### 4.1 三层信息

1. **原生事实**：谁在什么 Session/Message/Tool 调用中执行了什么，退出码、信号、时间、原始结果引用。
2. **项目自检**：项目测试／构建／浏览器断言的实际结果。测试内容本身仍需审查，不能保证语义正确。
3. **独立验收**：受保护的行为标准与输入，在干净导出副本中执行或由人员独立检查；这是实验结论的主要依据。

不要把模型生成的 JSON、工作区里的 `PASS` 文件或截图当成可信执行记录。共享 UID 的辅助脚本可被工作代码影响；若仅有此类记录，应明确标记为项目自报，不提升为平台认证。

结果显示至少区分：`PASS`、`FAIL`、`NOT_RUN`、`UNKNOWN`、`STALE`。需求结论另标 `SATISFIED`、`UNSATISFIED`、`NOT_VERIFIED`，不由 Shell 退出码自动等同产生。

### 4.2 执行不越权

保持原生工具。新增辅助只允许固定职责、结构化参数和授权项目路径；通过参数数组调用程序，不把用户文本拼成 Shell。依赖安装与项目脚本运行在独立工作环境的用户权限中，不在 guard／模型网关／宿主控制器权限中执行。

需要精确退出码时单独执行命令，或明确采集每段状态；不能用 `test; echo ok` 的最后退出码声称 test 成功。浏览器验证应覆盖输入、点击、最终状态等对应行为，而非只截图。

超时、中断、配额耗尽、断线标记准确。预算继承 v2；达到预算不由平台自发重试整个任务。只运行与问题有关的测试，不以增加调用轮次为“更认真”。

## 5. 证据与成果的版本绑定

### 5.1 不能只用 Git HEAD

记录项目输入基线、实际工作树内容标识（含相关未跟踪文件）、配置/依赖锁文件摘要、验证命令与结果、成果 SHA256。Git HEAD 未变并不代表文件未变。

不要把两次瞬时扫描当成原子快照：它不能排除扫描间写入或先改后还原。无法证明验证过程中输入稳定，就不能把结果标为当前成果已验证。

### 5.2 推荐最小、可证明的交付方式

沿用已实现的导出逻辑，针对其实际生成的不可变 ZIP／补丁字节记录摘要，然后在一个新建、受控、授权且隔离的临时副本上验证**这份导出物**。

- ZIP 解压后按已核实锁文件安装／验证，不读取用户原生会话或秘密。
- 补丁在对应干净基线应用，再运行相同的行为验收；保留二进制、增加、删除和符号链接的既有安全规则。
- 副本中执行项目代码的权限不能比原工作空间高；复用 v2 的资源预算与执行边界，不开启永久评测 Worker。
- 这类验证可以在受控验收流程中进行，不强迫每次聊天自动创建副本。产品界面必须准确说明“当前工作自检”与“导出副本验证”各自覆盖了什么。

工作区随后改变时，将历史验证显示为对应旧内容的记录。可以继续下载那份已验证的不可变成果；若导出新的当前内容，则不能沿用旧 PASS。若现有下载端点每次重新生成，需最小增加受鉴权的快照引用，或明确把新下载标为未验证，不能只复用旧文件名。

未实现验证副本功能前，T1 可以用真实受控验收证明下载复现，但产品不得展示自动认证标志。最终至少有一种用户看得懂、与实际字节匹配的交付证据路径。

### 5.3 保持范围

只保存小的、可审计的证据元数据和既有成果文件；不存第二份聊天状态、不新建通用 Artifact 平台。使用现有存储和鉴权，保留 v1 已修复导出规则。证据层读取原生事实，不驱动 Agent 再执行。

## 6. 生命周期与恢复

验证／导出期间沿用 v2 的保护机制，不能中途自动停止；只读成果页轮询不算用户活跃、不唤醒环境。只在用户明确进入／操作时执行。

停止和重进后保留已有会话、文件、证据引用；重进不能自动重复验证或恢复旧工具调用。预览和终端若已退出，显示需重启，不虚假恢复。

证据权限沿用当前用户—空间绑定。知道 Session、文件或证据 ID 不产生权限；生成内容中的 HTML 或脚本不在工作台可信来源直接执行。

## 7. 内核变更止损

如需修改上下文、任务循环或存储：先提交复现、最小候选、相关原生测试与维护代价，说明为何受控配置／工具不足。没有批准不进入深层改造。

发现为完成功能需要复制一套 Loop、Task Graph、恢复/重试系统时，冻结扩展并重新切小任务。产品价值不能靠放弃原生边界达成。
