# 开发、发布和回退

## 开发边界

在现有获准开发宿主创建独立候选，不操作退役远程部署或共享模型宿主。保护既有 Compose、数据卷、证书和用户文件；不全局 prune，不为节省空间删除历史冷备。

执行前确认实际入口，不把仓库旧文档中的端口、模型名、绝对路径当成现时有效。敏感文件只读必要字段，不能写进证据、聊天或 Git。

项目 case 副本只来自明确授权，且保留准确来源和基线。复制生产项目／数据库／用户会话不是默认权限。依赖安装与浏览器运行继承现有出口及资源边界。

## 固定候选

记录 WorkBench SHA、原生 OpenCode及 UI 摘要、镜像、批准的模型路由、项目指引／辅助脚本摘要。构建沿实际仓库支持的命令；本包不虚构可运行的发布命令。

临时使用本包 scripts 的检查，只证明资料结构；实际产品构建、测试与启动命令由实施者确认后写入交付说明。

优先用配置或局部发布替换指引与面板。与旧会话兼容；不能为更新指引清空原生会话。较旧证据保留其来源版本，不覆盖成新版本 PASS。

## 按需运行与容量

模型调用沿用 v2 共享网关，实验串行或在既有并发允许范围运行，不调整保护值来加速测试。有限任务集也要记录请求数，防止不必要的长循环。

证据副本和日志有上限及保留规则，路径由平台管理且可鉴权。临时副本清理只作用于本次明确创建的目录；用户工作文件、会话、未提交修改和导出物不能按模糊名称清理。

## 发布、回退、再部署

在隔离部署完成一次真实修复、下载复现、停机重进。备份保护项目和会话；只保存有用的脱敏证据到仓库。

回退优先回退制品与受控配置，不以恢复旧数据覆盖新用户修改。若持久结构必须改动，先提供兼容迁移和回退说明，否则本轮不做。

默认的 v3 签收范围是当前获准开发部署；生产推广要单独明确目标和授权，不隐含在“给 Codex 开发包”里。

## 发布前要有的说明

用户如何提问、会得到什么、哪里查看未验证项、怎样取得正确版本成果；当前支持的项目和缺陷范围；模型或依赖不可用时如何识别；停止重进的准确承诺；上一版本如何恢复。

保留本次用户签收的原文、时间和范围。不让代码生成工具填写“用户已认可”。

## 12. 本轮实际处置：候选不发布

r4 只在隔离的 `workbench-v2-checkpoint` 中运行。正式比较未满足冻结的 holdout 与 24 次请求上限，因此没有发布 v3。维护者在认证的 Qwen `/slots` 连续显示空闲、共享网关未决记录为空后，只替换受测的工程师原生容器、guard、共享网关和生命周期 helper 为 v2 固定制品；项目、OpenCode 状态和会话目录未重建。

回退后实际验证：平台与共享网关保持运行；工程师空间从 `STOPPED` 显式进入；原生会话列表共 46 条，两个指定 r4 会话仍存在；项目源文件没有变化；随后通过生命周期接口无强制停止并回到 `STOPPED`。脱敏结果见 [rollback-to-v2](evidence/rollback-to-v2.json)。

不得把私有实验目录当成发布源。当前发布源仍是 v2 的 `compose.release.json`、`lifecycle.release.json` 和固定制品 `cba249137c43c4b68162bf5bddf6ccf3f6b338d1`。若未来重新研究该假设，应先冻结新协议，不复用本轮 holdout 作为未见样本。


## 13. Luna 产品候选

用户已将产品目标从 Qwen 调整为 Luna。r5 的受控配置以 [Luna 配置](templates/OPENCODE_LUNA_PROFILE.json) 为公开规范：model 和 small_model 均为 approved/gpt-5.6-luna，Qwen 只作为维护者控制的非默认回退，不新增用户模型配置。

r5 先在隔离的 workbench-v2-checkpoint 中完成技术验收并回退。用户签收同一清单后，该精确候选被提升为只读本机发布源；只替换工程师原生容器、guard、共享网关和 lifecycle helper，项目、会话、额度、平台入口与资源名称保持。发布后只读核实默认 Luna 配置并正常停止。生产和退役远程部署仍未操作。
