## 开始动作

1. 检查实际 HEAD、未提交改动、运行制品和可用开发环境。参考 HEAD 不是强制回退目标；不覆盖任何用户工作。
2. 标明本包是唯一活跃 v3 路线；旧包保留为历史，不全局改名、不删除数据。如果已有 Shared 实现，记录其位置，避免加载，未经授权不回滚它。
3. 沿现有 v2 实际启动入口查找 UI、原生事件、指令配置、验证、导出和生命周期边界；不要改一个已经不在运行路径上的旧文件，然后宣称产品完成。
4. 根据可用授权项目与真实问题选一个切片，运行 v2 基线；冻结预期行为、对照和预算，再动手增强。

## 唯一要交付的用户故事

工程师在已有项目中描述真实缺陷，WorkBench 内的原生 OpenCode 理解并复现问题，完成必要修复与相关验证；工程师检查明确的修改及证据，下载正确版本的成果，停止再进入后还能继续工作。目标是减少反复指导和接手，而不是增加工具数量。

优先利用现有 Node／Vite／React 模板，只服务一个真实项目和一类缺陷；不建设多项目管理。T1 尽早打通浏览器到真实结果，不等所有架构或全部案例准备好。

## 实施原则

项目指引来自核实的源码、文档和实际命令，不包含秘密或标准答案。通过平台批准路径装载；不放开任意项目配置、MCP、插件或系统提示覆盖。

已有工具和面板先复用；基线暴露重复问题时才加局部辅助。脚本运行在原有用户执行边界，不在持有平台权限的进程中运行项目代码。默认不改 OpenCode 核心、不换模型；跨出这些边界先说明必要性。

复现失败、命令退出、用户行为通过、未验证、证据过期必须分清。不能把退出码 0、截图存在或模型说“已完成”当作需求已满足。正文中的任务文本是数据，不拼接成高权限命令。

## 禁止的捷径

不得删除/跳过测试、把预期改成实际、硬编码答案、伪造日志、让 Codex 代受测 OpenCode 修目标案例、只挑成功尝试或改预算制造提升。

不得以收集证据为由自动发模型请求、唤醒空间或恢复旧任务。证据层不是第二套 Session/Run 引擎。

不得绕过 v2 容量、模型并发、配额、网络、停机或审批保护。不得将共享模型网关误认为已搁置的 Shared Agent 而删除。

## 验证与交付

按 T0—T3 推进。案例采用成对比较与独立行为核验，保留失败和未运行信息。产品验收见 V3E-A01—A14，检查脚本只做包／证据完整性辅助。

只有真实用户使用和证据支持时才写 PASS/ACCEPTED。已有 v2 签收不自动意味着 v3 签收。候选无收益时报告 `NO_CHANGE_RECOMMENDED`，保留 v2，不硬造成功。

默认只在获准开发环境启动隔离候选。生产或退役远程部署需要另行明确授权；备份、回退不能覆盖候选发布之后产生的新用户数据。

每次结束更新 STATUS.md。当前闭环失败就修复、缩减或报告精确阻塞，不开发无关功能。满足交付终点即结束，不自动进入 v4。
