# v1 工作清单：一条新路径，四项有限工作

不是四个独立技术模块，也不是新版多阶段路线。T02 必须同时接通所需前端、绑定、部署和代理，不允许全部后端写完以后才看浏览器。

## T01 · 已有用户能取出完整、安全的成果

**先做：**登记实际 HEAD/工作副本差异与 `v0=USER_CONFIRMED_ACCEPTED`，只读定位现有部署；不做从零验收。运行包内导出契约以及已有相关测试。

**实现：**在实际仍有缺陷的路径修复合法源码漏导和 `.npmrc` 泄露，统一必要策略、明确排除原因；保留 fixed baseline、索引不变、链接边界和隔离 Git 元数据。当前已修好则只记录回归，不重构。

**主要位置：**`src/patch-export.ts`、`src/source-export.ts`、`src/snapshot-git.ts`、`src/environment-guard.ts` 和导出相关测试；只有 UI 需要展示新增信息时改成果面板。

**验收：**V1-A07、A08；一次真实下载的内容可检查。导出脚本必须是绿色，已存在的二进制/删除/链接测试不退化。

**终点：**当前用户不再因文件名被静默丢掉工作，也不从补丁带出受保护配置。不得趁机开发通用 Artifact 管理。

## T02 · 第二位工程师进入其真实项目并完成代码工作

**依赖：**T01。A 的基线可只读发现，B 的身份与项目必须合法获授权。

**实现一条线：**受控配置声明 B/P2 → 独立资源准备 → 企业入口和浏览器绑定 → 项目入口 → 原生 OpenCode 多轮修改/测试 → 正确预览/文件/Diff。保留 A 当前路径。

**主要位置：**`src/platform.ts`、`access-policy.ts`、现有 edge/preview/native proxy、部署脚本/Compose、UI 现有项目入口。按需求做小适配，不拆服务、不改 OpenCode。

**验收：**V1-A02、A03、A04、A05、A06。先在浏览器看到真正可以工作的 P2，不用只返回静态项目卡片结项。

**终点：**B 完成一个预先定义验收标准的真实修改；A 可以继续原工作。没有第二身份时离线测试可以完成，但真实登录验收保持 BLOCKED_EXTERNAL，不冒充已交付。

## T03 · B 下载成果、干净复现，再继续第二轮

**依赖：**T02。

**实现：**成果页显示项目/基线/捕获摘要及排除说明；下载调用沿用已有授权；验证针对实际 ZIP/patch 字节完成。补齐导出期间写入保护与错误语义，必要时局部参数化现有测试工具路径。

**验收：**V1-A09、A10、A11。第一轮下载在全新副本通过；再次登录继续有意义的第二轮修改，第二次成果与第二次验证对应。停止/断线不自动重发、不伪造成功。

**终点：**B 不依赖维护者临时改 DB、修文件或手工补包即可取得成果。不要把 PR、版本市场、自动发布加入本任务。

## T04 · 增量部署、原用户回归与 v1 签收

**依赖：**T01–T03。

**实现：**按受控维护方式发布本次必要制品/配置；增加 B 不改变 A 数据身份。更新当前有效 README/使用说明和版本映射；保留历史证据。做针对新增资源/改动路径的发布与回退验证。

**验收：**V1-A01、A12、A13、A14，以及所有其他项真实通过。已有 v0 的完整验收作为基线继承，只回归受影响面，不整套重开。

**终点：**发布包、增量说明、真实用户签收齐备，状态为 ACCEPTED；没有维护许可可写 READY_FOR_DEPLOYMENT，没有实际签收写 READY_FOR_USER_ACCEPTANCE。

## 过程纪律

每次“继续”只推进当前任务的未满足标准。新想法放 STATUS 的候选区，不自动变成下一张任务。第一条路径回归时暂停其他扩建；没有真实重复不抽象 Provider/Factory/Registry。
