# Codex 实施指令：WorkBench v1

你在已有 `dongfengguilai/workbench-opencode` 上做增量交付。请实际修改代码、构建、运行对应测试并整理部署结果，而不是只扩写本包。

## 首先接受这三个事实

1. 上一开发包和现有已交付产品叫 **v0**。用户已完成本人企业内网登录、整套部署和完整验收；不要重新打开这一问题。
2. 本次叫 **v1**。历史部署名 `WorkBench-v1` / `workbench-v1` 不因此重命名，不因此重建任何资源。
3. 已选定完整 OpenCode，纯云端托管，普通用户不配置工作环境。不得执行旧三阶段包，不引入本地连接器、Harness/Cordis、插件平台、多 Runtime 或新 Agent 循环。

先读 [BASELINE.md](BASELINE.md)、[PLAN.md](PLAN.md)、[TASKS.md](TASKS.md)、[ACCEPTANCE.md](ACCEPTANCE.md)、[STATUS.md](STATUS.md)，再按需阅读实际代码。遵守当前仓库已有安全与操作指令；遇到旧产品要求冲突，按 BASELINE 的最新版本映射记录，不擅自删文件。

## 只交付这一条新路径

第二位真实工程师进入其独立环境和另一个已有授权项目 → 用原生 OpenCode 完成真实修改/测试 → 检查并实际下载完整安全的成果 → 干净副本验证 → 重新进入继续第二轮。原有用户仍然可用且数据未损坏。

每人先一个项目，项目与环境由管理员预置。保留容器内 `/workspace/project` 约定。第二项目采用既有支持的语言/模板，不同时开新语言产品线。范围到此为止。

## 动手方式

- 先记录开发 HEAD 和未提交改动；不 reset、不清理未知目录、不覆盖旧系统。若实际代码已修复审阅问题，直接跑回归确认，不重复重构。
- 先完成 T01 的导出小闭环，再直接实施 T02 的第二用户纵向路径。不要先“做完所有模块”再接页面。
- 只在已确认的差异处做小接口或配置化。维持当前技术栈、OpenCode/前端固定版本、模型与认证方式。
- 可复用已有部署与授权入口；新增绑定生成前做 dry-run 和资源冲突检查。不向用户会话暴露任意 environment URL、路径、模型密钥。
- 没有第二身份/项目/入口条件时先从已有配置和说明发现；能完成的离线代码与测试继续完成，不能调用真实外部服务的点精确标阻塞。不得伪造第二用户，也不反复索取已确认的第一用户登录。
- 交付验证必须使用真实模型和真实项目。Mock 可用于单测，不能作为 A02/A03 等真实使用证据。
- 不读取或回显生产密码、模型主 Key、Token、私钥；认证由用户本人或既有受控凭据流程完成。不要请求用户在聊天中粘贴密码。

## 修改范围

优先在 `opencode-cloud/src/` 的身份绑定、代理/guard、导出，以及现有部署脚本、UI 项目入口、相关测试做局部改动。新增用户/项目绑定只需当前两个实例必需字段。新增记录放 `opencode-cloud/evidence/increment-v1/` 或本包状态文件；不覆盖历史 `evidence/v1-*`。

不允许重写 OpenCode 循环、上下文、SQLite Session、工具与 PTY；不允许改现有模型服务、其他业务容器、宿主机全局 TLS/安全设置；不允许迁移或清空原工作目录、会话库、预算文件、用户证书。

## 生产操作

实现授权不等于破坏性生产操作授权。先在开发/预发布或第二个独立实例验证。复用现有受控发布程序，只操作本项目的明确资源。对于既有用户需要停机、替换入口或证书的切换，提供变更/回退清单并在获准维护窗口实施；未获得权限时报告 `READY_FOR_DEPLOYMENT`，不能偷偷中断现有工作。

发布回退优先回退代码、配置与路由，不自动拿旧数据备份覆盖新会话。维护前有任务运行就拒绝破坏性动作，不用 `force-recreate` 或 `down -v` 解决阻塞。

## 验收与停止

- 当前任务只以 ACCEPTANCE 的用户结果验收，不以文件数量、模块数量或“所有 Mock 测试通过”结束。
- 发现原有流程回归时，暂停新功能，修复回归；不要扩建无关能力。
- 状态只允许：`NOT_STARTED` / `IN_PROGRESS` / `BLOCKED_EXTERNAL` / `READY_FOR_DEPLOYMENT` / `READY_FOR_USER_ACCEPTANCE` / `ACCEPTED`。
- `v0Baseline=USER_CONFIRMED_ACCEPTED` 保持独立。v1 新测试失败，不修改成“v0 未验收”。
- 真实工程師/产品负责人未签收 v1，不能将 v1 写成 ACCEPTED；但这不能用于否定用户已给出的 v0 签收。
- “继续”默认推进当前未完成验收，不自动启动下一版或增加新功能。
